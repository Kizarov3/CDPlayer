# Android stage 1, part 1: toolchain and background-playback gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove (or disprove) on Android emulators that CDPlayer's real Web Audio engine (`src/renderer/js/audio.js`)
keeps playing in a Capacitor WebView with the screen off for 30+ minutes, across track changes and a gapless seam,
under Doze — the spec's first gate. The rest of stage 1 gets its own plan after this result is reported to the user.

**Architecture:** A Capacitor 8 Android project at `android/`, web bundle assembled by `scripts/build-android.mjs`
into `dist-android/www` (gitignored). A small Kotlin plugin `PlaybackService` (foreground service, type
`mediaPlayback`, MediaSession, wake lock) keeps the process alive. A spike page plays local test files through the
unchanged `AudioEngine` and logs every seam and track change with timestamps to logcat.

**Tech Stack:** Capacitor 8.6.x (`@capacitor/core`, `@capacitor/cli`, `@capacitor/android` as devDependencies),
esbuild (bundling), Kotlin, `androidx.media` (MediaSessionCompat), Android SDK command-line tools, OpenJDK 21.

**Spec:** `docs/superpowers/specs/2026-11-20-android-design.md`

## Global Constraints

- Min SDK 29 (Android 10); compile/target the latest SDK installed (36).
- Application id `com.kizarov3.cdplayer`; app name `CDPlayer`.
- Capacitor packages and esbuild are **devDependencies** only (electron-builder packs production deps).
- The desktop app must not change behaviour; `npm test` passes before every commit.
- Work on branch `android` in a worktree; nothing pushed, tagged or released. No AI attribution in commits.
- Spike files are throwaway and live under `android-spike/` (gitignored), not `src/`.

## Review Focus

- Chromium throttles background timers to ≥1 s (or 1/min under intensive throttling) → `AudioEngine.watchSeam`'s
  timer-driven seam misses its moment; expected: seam still within ~50 ms of the file boundary, or the failure is
  recorded as the gate result (Task 3 logs seam error per seam).
- Doze/app standby kills or freezes the process while playing → expected: playback continues (Task 4 forces idle).
- `AudioContext` suspended when the activity stops → expected: still `running` (logged every minute in Task 3).
- Range requests on Capacitor's local server → seeking a FLAC/MP3 mid-file works (Task 3 seeks once per track).
- Audio focus loss from another player → pause, not silence-while-"playing" (Task 4 checks).

### Task 3: Spike — real `AudioEngine` + `PlaybackService`

**Files (throwaway, gitignored):**
- Create: `android-spike/www/index.html`, `android-spike/www/spike.entry.js`
- Create (kept if the gate passes): `android/app/src/main/java/com/kizarov3/cdplayer/PlaybackService.kt`,
  `PlaybackPlugin.kt`; register in `MainActivity.java`; manifest: `FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `WAKE_LOCK`, `POST_NOTIFICATIONS`, `READ_MEDIA_AUDIO`,
  `READ_EXTERNAL_STORAGE maxSdkVersion=32`, service `foregroundServiceType="mediaPlayback"`.

**Interfaces:**
- `PlaybackPlugin` (JS name `Playback`): `start({ title, artist })`, `update({ title, artist, playing,
  position, duration })`, `stop()`; event `command` `{ action: 'play'|'pause'|'next'|'previous'|'seek', position? }`.
  The service holds a partial wake lock while playing and keeps the WebView from being paused (override
  `MainActivity.onPause`/`onStop` so the bridge's WebView keeps running: don't call `webView.onPause()` /
  `pauseTimers()` while the service runs).
- Spike: imports `AudioEngine` from `src/renderer/js/audio.js` (bundled by esbuild); plays a fixed list of files in
  `/sdcard/Music/cdp-test/` via `Capacitor.convertFileSrc`, uses `prepare` + the engine's own seam for gapless,
  seeks each track to 30 % once, and logs to `console` (→ logcat `Capacitor/Console`):
  `SPIKE seam <n> err_ms=<boundary error> ctx=<state> t=<Date.now()>` and `SPIKE tick ctx=<state> pos=<s>` every 60 s.

- [ ] **Step 1:** Make test music: with ffmpeg generate a "gapless album" (one 30-minute sine sweep split into 12
  FLAC files at sample-exact boundaries) plus one MP3 and one M4A; `adb push` to `/sdcard/Music/cdp-test/`.
- [ ] **Step 2:** Write plugin + service + spike; build with `--entry android-spike/www`; grant permissions
  (`adb shell pm grant`); press play; confirm logcat shows seams and ticks with the screen on.

### Task 4: Run the gate and report

- [ ] **Step 1 (cdp-pixel):** play, `adb shell input keyevent KEYCODE_SLEEP`, wait 35 min; then
  `adb shell dumpsys deviceidle force-idle` mid-run. Pass = every seam logged with |err_ms| ≤ 50, ticks every
  ~60 s with `ctx=running`, no gaps in ticks > 90 s, notification present (`dumpsys media_session`).
- [ ] **Step 2:** Media buttons: `adb shell cmd media_session dispatch pause|play|next` change playback.
- [ ] **Step 3:** Audio focus: start another player (`adb shell am start -a android.intent.action.VIEW -d
  file:///sdcard/Music/cdp-test/x.mp3 -t audio/mpeg`) → the spike pauses.
- [ ] **Step 4 (cdp-low):** repeat Step 1 for 35 min.
- [ ] **Step 5:** Write `docs/superpowers/specs/2026-11-20-android-gate-result.md` (versions, logs summary, pass/fail
  per check, what only a real phone could show). Commit `PlaybackService`/`PlaybackPlugin`, build script and config;
  report to the user in Russian. If failed: describe the ExoPlayer fallback plan and stop for the user.
